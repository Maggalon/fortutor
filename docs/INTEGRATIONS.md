# Подключение интеграций

Значения ниже задаются в `.env.local` для разработки и `.env.production` на VPS. Web и worker используют одни и те же PostgreSQL, Redis, S3 и bot/API keys. После изменения ключей пересоздавайте оба контейнера с `--force-recreate`: обычный `docker compose restart` не обновляет окружение. Не добавляйте секреты в `NEXT_PUBLIC_*`. Первый deployment возможен с пустыми ключами ЮKassa; подключение магазина, автоплатежей и чеков описано в [BILLING.md](BILLING.md).

## Окружение

| Переменная                                    | Назначение                                                                                                                             |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `DEMO_MODE`                                   | В production строго `false`                                                                                                            |
| `APP_URL`                                     | Канонический адрес без завершающего `/`, например `https://tutor.example.com`; используется в приглашениях, webhooks и проверке Origin |
| `DATABASE_URL`                                | PostgreSQL URI; пароль URL-encode, если есть специальные символы                                                                       |
| `DATABASE_SSL`                                | `true` для облачного PostgreSQL с доверенным TLS; `false` для внутренней Docker-сети                                                   |
| `REDIS_URL`                                   | `redis://...` или `rediss://...` с паролем и номером DB; постоянный Redis с поддержкой BullMQ/Lua                                      |
| `S3_ENDPOINT`                                 | Endpoint S3-провайдера; для AWS можно оставить пустым                                                                                  |
| `S3_REGION`, `S3_BUCKET`                      | Регион и приватный bucket                                                                                                              |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`    | Ключи доступа только к bucket приложения                                                                                               |
| `S3_FORCE_PATH_STYLE`                         | `true` для провайдеров, требующих path-style (например MinIO); иначе `false`                                                           |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` | Токен и username без `@`                                                                                                               |
| `TELEGRAM_WEBHOOK_SECRET`                     | Независимый случайный секрет webhook                                                                                                   |
| `MAX_BOT_TOKEN`, `MAX_BOT_URL`                | Токен официального API и публичная ссылка бота                                                                                         |
| `MAX_WEBHOOK_SECRET`                          | Другой случайный секрет webhook                                                                                                        |
| `MAX_API_URL`                                 | По умолчанию `https://platform-api2.max.ru`                                                                                            |
| `DEEPSEEK_API_KEY`                            | Ключ DeepSeek с доступным балансом                                                                                                     |
| `DEEPSEEK_MODEL`                              | По умолчанию `deepseek-flash`; доступная модель выбранного аккаунта                                                                    |
| `DEEPSEEK_API_URL`                            | По умолчанию `https://api.deepseek.com`                                                                                                |

В Linux секрет можно сгенерировать `openssl rand -hex 32`. Для Telegram используйте допустимые символы secret_token (hex подходит). Не используйте одинаковые секреты двух webhook-каналов.

## Telegram

1. Создайте бота через BotFather, получите token и username.
2. Заполните три Telegram-параметра. Откройте публичный `APP_URL` по HTTPS и проверьте `/api/health`.
3. Выполните `pnpm bots:setup` локально с `.env.local` либо команду настройки из инструкции VPS. Скрипт устанавливает webhook `/api/webhooks/telegram`, secret_token и команды `/homework`, `/balance`, `/unlink`.
4. Ученик регистрируется по приглашению → «Настройки» → «Подключить Telegram» → открывает ссылку → Start. Ссылка одноразовая, действует 15 минут. Родитель открывает бота и отправляет код из карточки ученика. Код одноразовый; после использования в карточке появляется новый.
5. `/homework` или кнопка «Сдать ДЗ» запускает выбор предмета, задания, загрузку файла/фото, затем «Подтвердить отправку». До подтверждения работа не считается сданной. `/unlink` отключает привязки этого пользователя в данном канале.

Проверка webhook через API `getWebhookInfo`: смотрите pending_update_count и last_error_message. Для просмотра не вставляйте токен в публичные сообщения или логи CI. [Официальная документация Telegram](https://core.telegram.org/bots/api#setwebhook).

## MAX

1. Зарегистрируйте бота по действующим правилам официального портала MAX, получите token и публичную ссылку. Возможность создания бота зависит от доступа вашего аккаунта на стороне MAX.
2. Заполните MAX-параметры. `MAX_BOT_URL` — ссылка на бота, без query-параметров; приложение добавляет `?start=...` для привязки ученика.
3. Запустите `bots:setup`. Создается подписка на `bot_started`, `message_created`, `message_callback`, endpoint `/api/webhooks/max`.
4. Ученик использует кнопку MAX в своем кабинете; родитель отправляет код. Диалог сдачи ДЗ такой же, как в Telegram. Входящие фото/файлы скачиваются с разрешенных HTTPS-доменов MAX и сохраняются в S3.

API получает токен в заголовке `Authorization`. Webhook проверяет `X-Max-Bot-Api-Secret`. Endpoint должен отвечать на HTTPS/443 с действующим сертификатом; событие сначала сохраняется в PostgreSQL, тяжелая обработка выполняется worker. [Подписки MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions), [отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages), [медиа](https://dev.max.ru/docs-api/use-cases/sending-messages/media).

Если бот не отвечает: проверьте token, актуальный домен API, подписку, работоспособность worker, секреты и формат публичной ссылки. После долгой недоступности endpoint MAX может отключить подписку; повторите `bots:setup`. Если MAX меняет media CDN, добавляйте новый домен в `readMedia()` только после сверки с официальной документацией.

## DeepSeek

Для генерации отчета требуется API-ключ. Согласия собираются вне платформы; приложение не хранит и не проверяет флаг согласия. Передаются имя/предмет, период, посещаемость и проверенные задания с баллами/комментариями; платежные реквизиты, bot chat IDs и файлы не передаются.

«Отчеты» → «Сформировать отчет»: выберите ученика и период. Worker вызывает `/chat/completions`, сохраняет текст и ставит сообщения родителям в очередь. Статус «готов» означает, что текст сформирован; состояние доставки видно в задачах настроек. Без подключенного родителя отчет сохраняется в кабинете. Автоотчеты запускаются только для учеников с родительской привязкой: каждые 14 или 30 дней, начиная с создания профиля/последнего готового отчета.

При ошибке ключа, лимита или API задача повторяется до 5 раз; затем ее можно перезапустить в настройках. [Официальный Quick Start DeepSeek](https://api-docs.deepseek.com/quick_start). Название модели задается окружением, чтобы менять его без изменения кода.

## S3 и загрузка файлов

Создайте **приватный** bucket. Ключ приложения должен иметь `s3:PutObject`, `s3:GetObject` (включая HeadObject и CopyObject source); CopyObject требует PutObject на destination. Ограничьте доступ ARN этого bucket и его объектов. Public ACL не нужны. Для ботов S3 должен быть доступен из worker; для браузера — из сети пользователя.

Web загружает файл прямо в S3: `presign` → PUT временного объекта → `complete`. Сервер копирует его в отдельный окончательный объект, проверяет размер, Content-Type и сигнатуру. Продолжающая действовать ссылка PUT не может изменить уже приложенный файл. Не подтвержденные файлы нельзя прикладывать или скачивать. Подписанные ссылки действуют 5 минут; подтверждение допускается в течение 15 минут.

Установите bucket CORS (в консоли провайдера или AWS CLI; замените адрес своим):

```json
[
  {
    "AllowedOrigins": ["https://tutor.example.com", "http://localhost:3000"],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 300
  }
]
```

Для AWS CLI оберните массив в `{"CORSRules": [...]}` и выполните `aws s3api put-bucket-cors --bucket YOUR_BUCKET --cors-configuration file://cors.json`. Не добавляйте wildcard origins для production. Настройте lifecycle: удаление объектов префикса `staging/` через 1 день. Окончательные объекты автоматически не удаляются: резервируйте их и задавайте срок хранения согласно своей политике. Неудачные/брошенные загрузки могут оставить неиспользуемые окончательные объекты; массовая очистка должна сверять ссылки PostgreSQL.

Лимиты: JPG/PNG/PDF, один файл до 20 МБ, максимум 10 файлов в одной работе. Проверка сигнатуры не заменяет антивирус: скачивание всегда идет как attachment. Бинарные web-файлы загружаются напрямую в S3, поэтому Nginx Proxy Manager пропускает только небольшие запросы API.
