# Подписка For Tutor и ЮKassa

Один тариф для частного репетитора: **14 дней бесплатно без карты**, затем **1190 ₽ за календарный месяц**. Ученики и родители отдельную подписку не покупают. Учет оплат занятий (`ft_payments`) остается отдельным, ручным.

## Правила доступа

- Новый преподаватель получает ровно 14 × 24 часа от регистрации. Уже существующие аккаунты при первой миграции v2 получают 14 дней с момента миграции; повторный запуск миграции период не продлевает.
- Досрочная оплата добавляет месяц после более поздней из дат: окончания trial, оплаченного периода, текущего момента.
- Месяц календарный, время хранится в UTC. Если нужного числа нет, дата ограничивается последним днем следующего месяца: 31 января → 28/29 февраля. Следующее продление отсчитывается от полученной даты.
- Автопродление выключено по умолчанию. Checkout с отмеченным согласием сохраняет его версию/время и запрашивает сохранение способа оплаты у ЮKassa. Если способ не сохранен, автопродление отключается.
- В конце оплаченного периода worker создает автоплатеж. После подтвержденного отказа повторяет попытку через сутки, максимум три попытки в пределах 3 дней. У платного клиента с включенным автопродлением и сохраненным способом оплаты доступ действует еще 3 дня. У trial и ручного продления льготного периода нет.
- Отключение автопродления сохраняет оплаченный срок. Уже отправленный в банк платеж может завершиться; поздний webhook не включает автопродление снова.
- После окончания доступа преподаватель и ученики могут войти, просматривать и скачивать свои данные. Учебные изменения/загрузки, сдача ДЗ, новые отчеты и исходящие учебные уведомления блокируются. Профиль и отключение bot-привязок остаются доступны. Платеж/экспорт доступны преподавателю. Данные автоматически не удаляются.
- Предупреждения о сроке, ошибках и повторной попытке показываются в кабинете. Email/SMS уведомления о подписке в эту версию не входят.
- Оператор может выдать отдельному преподавателю бесплатный бессрочный доступ (`freeAccess`). Он действует для всего его кабинета, включая учеников, и не зависит от trial или оплаченного срока. Checkout и автопродление отключены; в кабинете показывается бесплатный статус без даты окончания.

## Первый запуск без ЮKassa

Магазин можно подключить после размещения сайта и его проверки. Для первого deployment оставьте в `.env.production`:

```dotenv
YOOKASSA_SHOP_ID=
YOOKASSA_SECRET_KEY=
YOOKASSA_TEST_MODE=false
YOOKASSA_RECEIPTS=false
YOOKASSA_VAT_CODE=
YOOKASSA_TAX_SYSTEM_CODE=
```

Дополнительный флаг не нужен: отсутствие обоих ключей отключает прием платежей. Проверка deployment пропускает настройки ЮKassa; остальные обязательные настройки PostgreSQL/Redis/S3/HTTPS сохраняются. Один заполненный ключ при пустом втором считается ошибкой.

Платформа работает в production с регистрацией и 14-дневным trial. В разделе «Подписка» показано сообщение о недоступности платежей, кнопки оплаты/проверки и checkbox согласия отключены. Checkout возвращает 503 без создания заказа; worker пропускает платежный tick и продолжает учебные задачи. Trial начинается при регистрации и не продлевается автоматически в ожидании магазина; после его окончания остаются просмотр, скачивание и экспорт. При необходимости владелец может явно предоставить доступ отдельному преподавателю командой `grant`, описанной ниже.

После проверки сайта заполните **оба** ключа, настройте режим/чеки и webhook согласно следующему разделу. Из каталога deployment на VPS примените изменения к текущим готовым образам:

```sh
set -a
source .release
set +a
docker compose --env-file .env.production -f deploy/compose.production.yml run --rm --no-deps migrate node --import tsx scripts/check-config.ts
docker compose --env-file .env.production -f deploy/compose.production.yml up -d --no-deps --no-build --force-recreate --wait --wait-timeout 180 web worker
```

Выполняйте вторую команду только после успешной проверки конфигурации. Пересборка и повторная доставка образов не требуются: ключи читаются при запуске контейнеров. Обычный `docker compose restart` не подхватывает изменения env-файла. Регистрации, данные и даты доступа сохраняются.

## Настройка магазина

1. Создайте магазин ЮKassa и получите Shop ID/секретный API-ключ. Уточните подключение автоплатежей для этого магазина.
2. Сначала используйте отдельный тестовый магазин и `YOOKASSA_TEST_MODE=true`. Web/worker должны иметь одинаковые значения.
3. В `.env.production` заполните:

```dotenv
YOOKASSA_SHOP_ID=YOUR_SHOP_ID
YOOKASSA_SECRET_KEY=YOUR_SECRET_KEY
YOOKASSA_TEST_MODE=true
YOOKASSA_RECEIPTS=false
YOOKASSA_VAT_CODE=
YOOKASSA_TAX_SYSTEM_CODE=
```

4. В кабинете ЮKassa настройте входящие HTTP-уведомления на `https://YOUR_DOMAIN/api/webhooks/yookassa`: `payment.succeeded`, `payment.canceled`. `payment.waiting_for_capture` также принимается, но платежи создаются одностадийными (`capture=true`). Возвраты не подписывайте на этот endpoint.
5. Проверьте доступность endpoint по HTTPS без Access List/Basic Auth/redirect. Для приема webhook не используется cookie или Origin. Приложение сверяет платеж через аутентифицированный GET к API ЮKassa, затем проверяет магазин, локальный заказ/tenant, сумму, RUB и режим test. Входящий JSON сам по себе не дает доступ.
6. После приемки замените ключи на ключи настоящего магазина, поставьте `YOOKASSA_TEST_MODE=false`, повторите настройку webhook в настоящем магазине и пересоздайте web/worker командами выше. Не смешивайте тестовые и реальные подписки: для тестирования используйте отдельную БД/установку. Сохраненные способы оплаты привязаны к своему магазину.

Карты не проходят через API For Tutor: преподаватель переходит на форму ЮKassa. На стороне платформы сохраняется только идентификатор способа оплаты; он не передается в frontend/экспорт. Цена зашита на сервере в `PRICE_KOPECKS=119000`; клиент не может прислать другую сумму.

## Чеки

Текущий исполнитель — самозанятый Новицкий Георгий Станиславович. Для этой схемы оставьте `YOOKASSA_RECEIPTS=false`: чек НПД формируется исполнителем через «Мой налог» и отправляется покупателю на email. Приложение не автоматизирует формирование и отправку чеков НПД. При возврате отдельно скорректируйте чек. Эти условия опубликованы на `/payment` и описаны в [LEGAL.md](LEGAL.md).

`YOOKASSA_RECEIPTS=true` добавляет в платеж `receipt` с email преподавателя и одной услугой «Доступ к For Tutor на 1 месяц» за 1190 ₽. Укажите `YOOKASSA_VAT_CODE` согласно настройкам своей услуги; `YOOKASSA_TAX_SYSTEM_CODE` — при необходимости. Чек использует `payment_mode=full_payment`, `payment_subject=service`; согласуйте эти параметры со своей схемой расчетов перед приемом настоящих денег.

Параметры не определяют вашу обязанность выдавать чек и не подключают кассу автоматически. Настройте сервис чеков/кассу в магазине. При `YOOKASSA_RECEIPTS=false` приложение не формирует receipt: используйте этот режим в тестовом магазине либо когда выдача чеков организована подходящим внешним способом. Не переносите примерный налоговый код в production без проверки.

Официальная документация: [сохранение способа оплаты](https://yookassa.ru/developers/payment-acceptance/scenario-extensions/recurring-payments/save-payment-method/save-during-payment), [автоплатежи](https://yookassa.ru/developers/payment-acceptance/scenario-extensions/recurring-payments/pay-with-saved), [webhooks](https://yookassa.ru/developers/using-api/webhooks), [чеки](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/yoomoney/payments), [коды и параметры чеков](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/yoomoney/parameters-values).

## Надежность

Локальный заказ и полный неизменяемый запрос сохраняются **до обращения к API**. Order ID используется как Idempotence-Key. Незавершенный заказ повторно используется при одновременных нажатиях checkout. Сетевые вызовы выполняются вне транзакций БД; результат применяется под блокировкой tenant. Успех помечается `appliedAt`, поэтому повторные/запоздавшие уведомления не добавляют месяц дважды. Return URL лишь открывает раздел подписки и запускает проверку.

Worker сверяет creating/pending платежи примерно раз в минуту, с учетом очереди и доступности провайдера. Если webhook пропущен, сверка все равно обновляет доступ. Статусы/события платежей сохраняются отдельно от краткоживущих bot receipts.

ЮKassa гарантирует идемпотентность 24 часа. Если после первого POST нет provider ID более 23 часов, приложение переводит заказ в `review` и прекращает POST. Оно **не начинает новое списание** с новым ключом. Проверьте заказ в кабинете ЮKassa по metadata `orderId`/`tutorId` и восстановите состояние через команду reconcile. [Официальный формат взаимодействия и срок идемпотентности](https://yookassa.ru/developers/using-api/interaction-format).

Неопределенный заказ блокирует новый checkout/renewal до разрешения оператором. Не удаляйте его и не меняйте Idempotence-Key вручную: это может привести к двойному списанию. После восстановления старого dump сверка платежей с провайдером обязательна до запуска worker. Успешный ручной checkout повторно используется еще 5 минут от создания, чтобы оплата из второго таба не создала дополнительное списание сразу после успеха первого.

## Поддержка через VPS

Команды доступны только пользователю с доступом к Docker и production-окружению. Публичного admin API нет. В каталоге проекта загрузите текущую пару образов:

```sh
set -a
source .release
set +a
```

Далее:

```sh
docker compose --env-file .env.production -f deploy/compose.production.yml run --rm --no-deps worker node --import tsx scripts/billing-admin.ts list
docker compose --env-file .env.production -f deploy/compose.production.yml run --rm --no-deps worker node --import tsx scripts/billing-admin.ts status tutor@example.com
docker compose --env-file .env.production -f deploy/compose.production.yml run --rm --no-deps worker node --import tsx scripts/billing-admin.ts free tutor@example.com confirm "Индивидуальный бесплатный доступ"
docker compose --env-file .env.production -f deploy/compose.production.yml run --rm --no-deps worker node --import tsx scripts/billing-admin.ts reconcile tutor@example.com PROVIDER_PAYMENT_ID
docker compose --env-file .env.production -f deploy/compose.production.yml run --rm --no-deps worker node --import tsx scripts/billing-admin.ts grant tutor@example.com 2026-12-01T00:00:00.000Z "Компенсация простоя"
docker compose --env-file .env.production -f deploy/compose.production.yml run --rm --no-deps worker node --import tsx scripts/billing-admin.ts revoke tutor@example.com confirm "Возврат подписки"
```

Grant задает дату доступа явно, не проводит платеж и не меняет согласие на автопродление. Revoke отключает автопродление и заканчивает trial/оплаченный доступ. Для изменений сохраняется событие с причиной в `ft_billingEvents`.

Free включает бессрочный доступ без платежа, отключает автопродление, очищает сохраненный способ оплаты/повторные попытки и отменяет еще не отправленные заказы. Уже отправленный платеж может завершиться: проверка известного provider ID и webhooks продолжают работать, но не включают автопродление. Заказ без provider ID, отправленный до выдачи бесплатного доступа, переводится в review без повторного POST и требует ручной сверки. Grant и revoke снимают бесплатный статус. Выдача доступа сохраняется в журнале как `admin-free-access`; email используется только для поиска существующего аккаунта, исключения в исходном коде нет.

Если после ручной сверки в магазине подтверждено **отсутствие** платежа по неопределенному заказу без provider ID, его можно закрыть командой `billing-admin.ts abandon EMAIL ORDER_ID "Причина и результат сверки"` в том же worker-контейнере. Это допускает новый checkout и требует уверенности, что деньги не списаны; при наличии платежа используйте reconcile. Операция сохраняется в журнале.

Возвраты проводятся оператором в ЮKassa; их автоматическое применение к сроку доступа не реализовано. После согласованного возврата используйте revoke либо grant с нужной датой. Возврат денег и изменение доступа — разные действия; не выдавайте revoke за банковский возврат. Перед revoke убедитесь, что нет незавершенного списания, которое впоследствии продлит доступ.

## Приемка перед продажами

На отдельной тестовой установке проверьте: регистрацию/trial; оплату до окончания trial; успех/отказ; возвращение до webhook; повторную проверку одного платежа; повторный webhook; сохранение способа оплаты; отключение автопродления до webhook; автоплатеж и отказ с повтором; блокировку учебных изменений при сохранении просмотра/экспорта; отсутствие доступа к чужой подписке; чек с выбранной конфигурацией магазина.

Ускоряйте сроки через тестовую БД, не изменением часов production-сервера. Автоматические тесты подменяют транспорт ЮKassa и не заменяют тестовый платеж настоящим API. Информационные страницы с реквизитами, условиями подписки/возврата и обработкой данных уже подготовлены: перед проверкой магазина разместите текущую сборку и проверьте их по [LEGAL.md](LEGAL.md). Лимиты количества учеников/общего объема хранилища/AI-квоты пока не введены; действуют исходные лимиты файла и задания. Контролируйте расходы S3/DeepSeek перед расширением аудитории.
