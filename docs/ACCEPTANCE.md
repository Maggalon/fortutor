# Проверка готовности и сквозная приемка

## Что уже проверено

04.10.2026 прошли 25 тестов без пропусков на отдельной PostgreSQL-базе и Redis: существующие бизнес-правила/интеграции и подписки, повторное применение платежа, проверка суммы/магазина/режима, отмена автопродления перед webhook, календарный месяц, льготный доступ, одновременный checkout, автосписание и остановка повторных запросов после неопределенного ответа. Telegram/MAX/DeepSeek/S3/ЮKassa transport в тестах подменен: это проверка приложения, а не подтверждение доступа к вашим реальным аккаунтам.

Production Docker web и worker собраны успешно. Раздел подписки проверен в браузере на desktop и мобильной ширине около 390 px; горизонтального переполнения нет. Платежные кнопки недоступны без ключей ЮKassa, пробный срок и экспорт отображаются.

Сквозной `scripts/smoke.ts` прошел против собранных production-контейнеров: регистрация, Secure cookie, trial/цена подписки, история платежей, запрет доступа ученика к billing, HTTP 402 на учебные действия и загрузки после истечения, сохранение просмотра/экспорта, Origin, приглашение/роль ученика, отправка и оценка ДЗ, урок/платеж, webhook secret и обработка события работающим worker. Реальный магазин ЮKassa/NPM/VPS требует отдельной приемки после настройки ключей и домена.

Перед открытием реального сервиса выполните шаги ниже с настоящими ключами, доменом и **тестовыми** учениками/родителями. Не используйте рабочих несовершеннолетних для технической приемки.

## 1. Кабинет и приглашение

1. Открыть production HTTPS-адрес, убедиться, что отсутствуют demo-кнопки и banner.
2. Зарегистрировать преподавателя с уникальным email и паролем от 12 символов. Выйти/войти, перезагрузить страницу.
3. В настройках указать timezone и тестовые реквизиты.
4. Создать двух учеников: поурочный и пакетный, объединить в группу.
5. Открыть карточку → создать приглашение → зарегистрировать ученика в отдельном браузере. Проверить, что повторное приглашение больше не работает и ученик не видит других учеников/оплаты преподавателя.
6. Проверить на телефоне навигацию, календарь, открытие/закрытие форм и сохранение; светлую и темную темы.

## 2. Расписание

1. Создать одиночный урок и серию на 4 недели для группы.
2. Проверить одинаковое локальное время каждой недели, отсутствие пересечений.
3. Отменить один урок, перенести другой. В календаре видны статусы и новая дата.
4. Подключить ученика к боту и создать урок приблизительно через 24 часа, другой через 2 часа. Дождаться очередного tick и сообщения. Повторные tick не должны создавать новые одинаковые напоминания.
5. Отменить будущий урок и проверить, что новое напоминание не ставится. При переносе сообщение соответствует новой дате.

## 3. Telegram и MAX

Повторить для каждого канала:

1. Из кабинета ученика нажать подключение → перейти в бота → Start. В настройках появляется активная привязка.
2. Родитель запускает бота, отправляет код из карточки ученика. Подтверждение привязки, код в карточке заменяется. Старый код не связывает другого родителя.
3. Учитель назначает групповое ДЗ: тема, текст, ссылка, PNG/PDF, deadline, максимум баллов. Ученику приходит уведомление.
4. `/homework` → предмет → задание → фото/файл → «Подтвердить отправку». До подтверждения работы нет в очереди проверки, после — появляется ровно одна.
5. Проверить отправку текстового ответа, отмену диалога, отклонение файла неподдерживаемого типа и повторную отправку на доработку.
6. Учитель ставит «На доработке» с комментарием. Ученик видит комментарий, может отправить исправление. После итогового балла приходит результат проверки.
7. ДЗ на завтра/сегодня создает предусмотренные напоминания; уже сданная работа не напоминается. Для проверки не меняйте часы production-сервера: используйте подходящие deadline или тестовые часы в отдельной среде.
8. Выполнить `/balance` у родителя, `/unlink`, проверить исчезновение привязки. Повторное подключение — только новым кодом/ссылкой.

Web-сдача: открыть актуальное ДЗ в кабинете ученика, добавить реальный JPG/PNG/PDF, отправить, открыть файл у преподавателя. Попытка скачать этот файл из другого student-аккаунта должна вернуть 404/403.

## 4. Оплаты

Поурочная схема:

1. Провести урок с посещением. Появляются долг по конкретной дате и сообщение родителю с реквизитами.
2. Изменить стоимость будущих уроков: старый долг сохраняет старую цену.
3. Нажать «Внести оплату», выбрать урок, сохранить. Долг закрыт, запись в истории. Повторное закрытие того же урока недоступно.

Пакетная схема:

1. Внести пакет 2 занятия; остаток 2.
2. Провести посещенный урок; остаток 1, родителю уведомление о пополнении.
3. Провести еще два урока; остаток −1, сообщение о долге.
4. Пополнить пакет, проверить баланс и историю.
5. Отмена/пропуск ученика не списывают пакет. Повторное проведение одного урока не списывает еще раз.

Сообщение «поставлено в очередь» не означает банковский платеж: учет остается ручным.

## 5. DeepSeek

1. Подключить ключ.
2. Провести несколько уроков, проверить минимум два ДЗ с разными оценками и комментариями.
3. Сформировать отчет за период с этими событиями. Он проходит pending → ready, сохраняется в кабинете, приходит родителю через подключенные каналы.
4. Проверить правильность периода/посещений/баллов и отсутствие выдуманной динамики. Качество текста оценивается вручную.
5. Проверить, что ручные и автоматические отчеты работают без флага согласия. Ошибка API/исчерпанный баланс приводит к retry, затем failed с возможностью перезапуска.
6. Включить период 14/30 дней; проверить планирование автоматического отчета на тестовом окружении с соответствующими датами данных. Автоотчет требует родительской привязки.

## 6. Эксплуатационная приемка

- GitHub PR не может слиться в main без успешного verify; main выпускает только проверенный SHA.
- HTTPS и `/api/health` работают, PostgreSQL/Redis закрыты от публичной сети.
- Остановить worker на тестовой среде, принять webhook, запустить: событие остается и обрабатывается.
- В тестовой среде вызвать отказ провайдера, убедиться в retry/failed, затем восстановить и перезапустить задачу.
- Создать dump PostgreSQL и восстановить в **отдельной тестовой базе**, проверить доступность файлов по резервной копии S3.
- Проверить уведомление мониторинга при недоступности web и отдельное наблюдение за worker.
- Убедиться, что GitHub собирает образы до отправки на VPS, а сервер запускает готовые образы без build; другие Compose-проекты/NPM продолжают работать.

## 7. Подписка

На отдельной установке с тестовым магазином ЮKassa:

1. Регистрация дает 14 дней, цена 1190 ₽, автопродление выключено, карта не требуется.
2. Оплата без автопродления открывает месяц после текущего периода. Return URL до webhook не дает неоплаченный доступ.
3. Повторный webhook/проверка/одновременное нажатие не добавляют второй месяц. Отказ не продлевает срок.
4. Оплата с согласием сохраняет способ оплаты. Отключение автопродления сохраняет оплаченный доступ; поздний webhook не включает его снова.
5. Автоплатеж запускается worker после окончания периода. Подтвержденный отказ создает повтор через сутки, не более трех попыток за 3 дня.
6. После истечения ученик/преподаватель видят свои данные; создание, ДЗ и upload получают 402; JSON-экспорт и скачивание доступны. Боты не обходят ограничение.
7. Проверить конфигурацию чеков на тестовом магазине и команды поддержки. Список неопределенных оплат требует ручной сверки, новое списание после 23 часов не создается автоматически.

Критерии считаются подтвержденными в конкретном deployment после прохождения пунктов 1–7 с настроенными интеграциями. Автотесты и локальная демонстрация не заменяют финальную проверку внешних доступов.
